# US-21 · Valores curados

Usar uma **cópia** de `us-21.board.json`, com dados fictícios, esquema base v3 e extensão `project` v1. Importar pelo seletor para editar. Este comportamento **substitui a criação livre de membros nas tarefas prevista inicialmente na #35**: adicionar/renomear membros e criar tags só nas definições.

1. Abrir settings pelo ícone junto ao nome: membros Ana, Rui e Membro livre; tags bug, feature, improvement, documentation. Remover Membro livre e documentation: permitido porque não estão em uso. Remover Ana ou bug: bloqueado; retirar/substituir as atribuições primeiro, incluindo tarefas arquivadas.
2. Adicionar membro `Marta` e tag ` Delivery `; guardar. Reabrir: tag normalizada para `delivery`, listas persistidas. Tentar `marta` como outro membro e ` DELIVERY ` como outra tag: rejeitar duplicados. Tag vazia ou com mais de 30 caracteres: erro sem perda do rascunho.
3. Criar/editar workitem: responsável, participantes e tags são seletores do projeto, não campos de texto livre. Escolher Marta como responsável adiciona-a também aos participantes. Remover o participante responsável pede confirmação; cancelar mantém ambos e confirmar limpa o responsável.
4. Valores já selecionados não podem ser adicionados de novo. O limite existente de dez tags por workitem mantém-se. Listas vazias são válidas: a tarefa pode ser guardada sem pessoas/tags, mas não cria valores novos.
5. Abrir outro projeto com membros/tags diferentes: esses valores não aparecem nas escolhas do primeiro projeto. Mesmo nome em projetos diferentes não une identidades.
6. Paleta: atribuir/definir responsável oferece só os membros do projeto da tarefa, incluindo membros ainda sem tarefas. Escrever nome desconhecido não oferece «Adicionar pessoa».
7. Criação rápida `+ Teste @Marta #delivery`: cria apenas quando os valores pertencem ao projeto de destino. `+ Teste @Desconhecido #delivery` ou `+ Teste #typo` mostra aviso e não oferece Criar. Usar `in:` para trocar o destino: validar contra as listas desse destino, independentemente da ordem dos tokens.
8. Reabrir o ficheiro: manter catálogos, IDs e atribuições. Consultar/restaurar a timeline antes/depois de renomear/remover um membro livre: versões históricas continuam coerentes.
9. Criar projeto novo: Planeado, membros vazios e tags iniciais `bug`, `feature`, `improvement`, `documentation`. É possível eliminar todas as tags não utilizadas. Ficheiros legados, pelo contrário, recebem apenas os nomes/tags já utilizados, sem adicionar defaults artificialmente.
10. Testar teclado, PT/EN, claro/escuro e abertura só de leitura; não é necessário nem utilizado backend.

Verificação: `npm run test:unit` e `npx playwright test tests/e2e/project-settings.test.ts tests/e2e/task-editor.test.ts tests/e2e/palette.test.ts`.
