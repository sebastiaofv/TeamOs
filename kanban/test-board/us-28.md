# US-28 · Alterações concorrentes sem sobrescritas silenciosas

Usar o branch `codex/us-28-concurrent-project-reconciliation` e uma cópia de
[us-28.board.json](us-28.board.json). Abrir **o mesmo ficheiro** por Import Projects
em duas janelas/separadores (A e B). A cópia é necessária porque os testes gravam.
O board começa em `meta.revision: 0` e não tem histórico: a primeira edição
cria a mesma identidade de baseline nas duas sessões.

| Cenário | Passos | Resultado esperado |
| --- | --- | --- |
| Edições independentes | A muda o título de «Preparar proposta»; B muda «Rever orçamento» imediatamente depois. | As duas alterações ficam no ficheiro; B vê «Integradas N alterações…» e pode consultar os detalhes; nenhum diálogo automático. |
| Campos independentes | A muda a descrição e B o título do mesmo workitem. | São preservados os dois campos. |
| Mesmo campo | A e B mudam o mesmo título para valores diferentes. | B mantém o título local; surge aviso persistente com Resolver. A gravação automática desse projeto está pausada. |
| Decisão individual | Abrir Resolver; comparar Base / Meu / Externo e escolher o valor de cada campo. | Aplicar decisões e guardar mantém as escolhas e todas as alterações independentes; o histórico termina no checkpoint `board.reconciled`. |
| Eliminar / editar | A elimina um workitem que B editou. | O elemento aparece como conflito de eliminação/edição; nada é gravado até existir decisão. |
| Adiar / Escape | Adiar o diálogo e editar o segundo workitem em B. | O conflito continua visível; nenhuma destas alterações sobrescreve o ficheiro externo. |
| Recuperar | Com conflito em B, recarregar a página e aceitar o aviso do browser; importar o mesmo ficheiro. | Surge Recuperar alterações. Recuperar repõe o trabalho local e reconcilia contra o ficheiro atual. A cópia só é removida depois de transferida para a recuperação desta sessão. |
| Mudança durante decisão | No diálogo de B, escolher os meus valores; A volta a mudar o campo; B confirma. | O novo valor externo é detetado antes de gravar e exige nova escolha. As escolhas ainda aplicáveis mantêm-se. |
| Regressão | Com o projeto aberto, repor uma cópia mais antiga do ficheiro (ou conteúdo diferente com revisão igual). | Não há integração automática; todas as diferenças de conteúdo precisam de revisão explícita. |
| Compatibilidade | Remover apenas `meta.revision` de uma cópia antes de a importar; editar e guardar. | Abre normalmente e a primeira gravação escreve revisão 1. |
| Dois separadores | Guardar alterações independentes quase simultaneamente em dois separadores do mesmo browser/origem. | Web Locks serializa as gravações; as duas alterações permanecem. BroadcastChannel acelera a deteção. |
| Integridade | Em sessões diferentes, eliminar um elemento e criar uma referência para ele. | Os elementos relacionados aparecem juntos como conflito; não é gravado um projeto inválido nem descartada a relação por normalização. |
| Projeto independente | Manter um conflito num projeto e editar outro projeto aberto. | O segundo projeto continua a guardar normalmente. |

Os testes automatizados usam duas sessões Playwright sobre um ficheiro simulado
partilhado, incluindo recuperação IndexedDB real e aviso `beforeunload`:

```sh
npm run typecheck
npm run lint
npm run test:unit
npx playwright test tests/e2e/project-reconciliation.test.ts tests/e2e/project-files.test.ts
```

As verificações usam o hash do texto; `revision` apenas identifica regressões.
O browser não oferece uma operação atómica de comparação/escrita entre máquinas:
continua a existir uma janela entre a última verificação e a gravação. A releitura
posterior deteta conteúdo concorrente diferente que esteja então no disco.
Conflitos internos do OneDrive/Dropbox continuam fora do controlo da aplicação.
