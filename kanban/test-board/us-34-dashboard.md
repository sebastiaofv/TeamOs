# US-34 — Project Overview redesign

Open `us-9-sections.board.json`, select its project, and open Dashboard. Set Start date to 24/10/2026 and End date to 31/10/2026.

1. Six independent widgets appear first: Project progress, Active phases, Next / overdue milestones, Active sprint, Workitem status and Epics. The four widgets of [Progress Since Last Review](issue-83-progress.md) and the existing Project Control sections follow. The visibility selector can hide each widget; the four activity widgets also support shared visibility/order and Reset to Default. Overview widget management remains outside this story.
2. Project progress shows 30.8%, a progress bar and 4 completed / 13 eligible leaf workitems. Cancelled work and parent workitems are excluded; archived leaves remain included. Click the indicator to inspect sources.
3. Active phases contains parent and child phases in chronological order. Overdue parent phase is Overdue; API delivery, Delivery programme and UX delivery are On Target. Future parent phase is also included because its work has already started. Completed parent phase and the future, unstarted Empty phase are absent. Each row shows planned start/end dates and completion. A phase with a missed start but a future deadline and no started work is Late; an unfinished phase past its end date is Overdue.
4. Milestones contains every overdue pending checkpoint and only the next future checkpoint, Next unassigned checkpoint. Each row includes date, completion and Next/Overdue. Click a name to open its existing detail. Existing deliverable acceptance gates and unavailable denominators remain in force.
5. Active sprint retains its name, date range and planning-unit completion (0%). It also shows the Story count (1), planned SP / capacity (0 / N/A for this legacy fixture), completed SP (0) and On Target. Explicitly active Sprints remain visible after their deadline with Overdue. Completion points reuse development completion, including Stories whose Tasks are done but whose functional validation is pending. Child Tasks do not duplicate planning-unit points. Empty projects show a discreet no-active-sprint message.
6. Workitem status shows three horizontal stacked bars: User Stories, independent Tasks and Bugs. Each state uses its actual workflow name and color, with quantity and percentage in the legend. Independent Tasks total 9 across the entire project; Testing remains separate from In progress. Child Tasks under Stories/Bugs are excluded; Tasks directly under Epics remain independent. Click a legend entry to inspect its exact workitems.
7. Epics contains Delivery epic with its effective In progress status, 0% and a progress bar. Its progress uses the same direct-child calculation as Epic details. Unstarted and cancelled Epics are omitted; completed Epics remain included. Both ID and title open read-only details using the selected historical data.
8. Start/End dates continue to control historical snapshots and activity. Changing Start affects period activity; status widgets follow End. Dates before the first baseline show N/A. Invalid periods show the existing validation. Planning Scope and Recorded History are absent; the snapshot selector and date filters retain historical consultation.
9. Sprint Analytics retains its existing contents and interactions. Repeat navigation, legend drill-down and historical details in English/Portuguese, light/dark and at 390px width. Widgets keep preset dimensions and scroll internally; the page has no horizontal overflow. Consultation must not change the project file.
