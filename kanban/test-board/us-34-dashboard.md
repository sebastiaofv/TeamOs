# US-34 — Project Overview redesign

Open `us-9-sections.board.json`, select its project, and open Dashboard (last button in the main navigation). Open **Dates** and set Start date to 24/10/2026 and End date to 31/10/2026.

1. Overview and Sprint Analytics sit in the next navigation row. On the right, the compact Visible sections icon precedes Dates; its field shows both dates separated by a dash. Escape and clicking outside close either menu. Dates keeps the saved snapshot selector; the information icon explains reporting rules.
2. Project Overview groups six independent widgets above Progress Since Last Review, with larger headings and matching icons. Visible sections can hide each widget; the four activity widgets retain shared visibility/order and Reset to Default.
3. Project progress shows 30.8%, a thin divider, 4 / 13 workitems and a progress bar. Cancelled work and parent workitems are excluded; archived leaves remain included. Blocked workitems are absent. Click the indicator to inspect sources.
4. Active phases shows all six parent phases chronologically in a connected horizontal sequence. API delivery and UX delivery are children and absent. Completed parent phase is green with a check; Delivery programme has an inner blue circle; future unstarted phases have blue outlines. Late/Overdue alerts take priority and highlight the missed start/end date in red. Percentages still aggregate descendant work and respect deliverable acceptance gates. Names open the Roadmap; percentages open sources. The diagram scrolls within the card on mobile.
5. Milestones shows all checkpoints chronologically in four compact columns: status, name, date, percentage/progress bar. Completed milestones show green; overdue ones red; other ones On Target in blue. Empty denominators remain N/A. Hover long names and open the milestone detail. Deliverable acceptance gates still apply.
6. Active sprint retains its name, date range, On Target/Overdue badge and planning-unit completion (0%). Its three indicators show 2 Workitems, 0 / 0 Story Points and 0% Progress for this legacy fixture. Workitems include Stories, independent Tasks and Bugs; dependent Tasks do not duplicate counts or points. Completion points reuse development completion. Explicitly active overdue Sprints remain visible; empty projects show a discreet message.
7. Workitem status has one aligned horizontal row each for User Stories, independent Tasks and Bugs, with actual workflow colors, quantities/percentages inside sufficiently wide segments, hover details and one shared legend. Independent Tasks total 9; child Tasks under Stories/Bugs are excluded and Tasks directly under Epics remain independent. Click a segment to inspect its exact sources.
8. Epics has four columns without headers: ID, title, effective status and shared progress/bar. Delivery epic shows In progress and 0%. Unstarted/cancelled Epics are omitted; completed Epics remain included. ID and title open read-only details using the selected historical data.
9. The date range controls historical snapshots and activity. Start affects period activity; status widgets follow End. Dates before the baseline show N/A, invalid periods show the existing error and the snapshot selector still supports historical consultation. Sprint Analytics retains its contents and interactions.
10. Repeat in English/Portuguese, light/dark and at 390px width. Check popover keyboard access, internal scrolling, long titles and no page overflow. Consultation must not change the project file. Activity layout persistence, reopening/reset and read-only behavior remain covered by [activity scenarios](issue-83-progress.md).
