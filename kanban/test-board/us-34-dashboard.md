# US-34 — Project Overview redesign

Open `us-9-sections.board.json`, select its project, and open Dashboard (last button in the main navigation). Open **Dates** and set Start date to 24/10/2026 and End date to 31/10/2026.

1. Overview and Sprint Analytics sit in the next navigation row. On the right, the compact Visible sections icon precedes Dates; its field shows both dates separated by a dash. Escape and clicking outside close either menu. Dates keeps the saved snapshot selector; the information icon explains reporting rules.
2. Project Overview groups six independent widgets above Progress Since Last Review, with larger headings and matching icons. Visible sections can hide each widget; the four activity widgets retain shared visibility/order and Reset to Default.
3. Project progress shows 31% inside a circular chart, a thin divider and 4 / 13 workitems on its right. Cancelled work and parent workitems are excluded; archived leaves remain included. Blocked workitems are absent. Click the indicator to inspect sources.
4. Active phases shows all six parent phases chronologically in a connected horizontal sequence. API delivery and UX delivery are children and absent. Completed parent phase is green with a check; Delivery programme has an inner blue circle; future unstarted phases have blue outlines. Late/Overdue alerts take priority and highlight the missed start/end date in red. Percentages still aggregate descendant work and respect deliverable acceptance gates. Names open the Roadmap; percentages open sources. The diagram wraps into rows on smaller screens; the card grows to show every phase without internal scrolling, and adjacent cards stretch to match. Circles remain round in Classic and Modern; phase names occupy two lines with ellipsis and full hover text.
5. Milestones shows icon-only totals for completed, delayed and all remaining checkpoints. The compact list contains the latest recorded completion through its tenth day, every overdue checkpoint and the next pending checkpoint, sorted by due date. The report end date controls the completion window; planned due dates are never used as completion dates. Completed baselines without a recorded completion date count in the summary but are omitted from the recent list. If there are no relevant rows, a quiet empty message appears. Completed milestones have green bars with no percentage; overdue milestones show a warning icon beside the date without a status column. Empty denominators remain N/A. Hover long names and open the milestone detail. Deliverable acceptance gates still apply.
6. Active sprint retains its name, date range, On Target/Overdue badge and planning-unit completion (0%). Its three indicators show 2 Workitems, 0 / 0 Story Points and 0% Progress for this legacy fixture. Workitems include Stories, independent Tasks and Bugs; dependent Tasks do not duplicate counts or points. Completion points reuse development completion. Explicitly active overdue Sprints remain visible; empty projects show a discreet message.
7. Workitem status has one aligned horizontal row each for User Stories, independent Tasks and Bugs, with actual workflow colors, continuous segments without gaps, counts inside sufficiently wide segments, percentages in hover details and one shared legend. Independent Tasks total 9; child Tasks under Stories/Bugs are excluded and Tasks directly under Epics remain independent. There are no source buttons on these bars and no empty source section below the Dashboard; other progress/activity drill-downs still open sources when selected.
8. Epics has compact rows without headers: small ID above a truncated title, workflow-colored dot and status, completed/total Story Points and a wide, thick progress bar with the rounded percentage to its right. The fixed-height widget scrolls internally for many Epics. Points reuse planning-unit estimates and development completion, including direct Tasks and Bugs while excluding dependent Tasks; historical consultation uses the selected hierarchy and estimates. Progress bars are thicker and green at 100%, with the percentage hidden on completion. Delivery epic shows In progress and 0%. Unstarted/cancelled Epics are omitted; completed Epics remain included. ID and title open read-only details using the selected historical data.
9. The date range controls historical snapshots and activity. Start affects period activity; status widgets follow End. Dates before the baseline show N/A, invalid periods show the existing error and the snapshot selector still supports historical consultation. Sprint Analytics retains its contents and interactions.
